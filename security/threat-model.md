# Threat model — rag-mcp-agent

Состояние на 2026-10-27. Документ живой: каждая находка пентеста (этап 6) и каждая
новая граница доверия (ACL, MCP-клиент) добавляются сюда.

## 1. Что защищаем (активы)

| Актив | Почему ценен |
|---|---|
| Документы базы знаний | Внутренние регламенты; после мультитенантности — данные разных организаций |
| Бюджет на LLM (Groq, Cohere) | Каждый вопрос = 4–6 платных вызовов; украденный доступ = «denial of wallet» |
| Секреты: `GROQ_API_KEY`, `COHERE_API_KEY`, `DATABASE_URL` | Доступ к провайдерам и к базе на запись |
| Системные промпты | Раскрытие упрощает обход guardrail |
| Целостность ответов | Система не должна выдавать выдумку или текст атакующего за факт из базы |

## 2. Границы доверия

```
 [Браузер] ──(1)──▶ [Next.js на Vercel: /api/ask] ──(2)──▶ [FastAPI на Render] ──(5)──▶ [Groq / Cohere]
                                                               │       ▲
                                                           (3) │       │ (4) текст документов
                                                               ▼       │     попадает в промпт
 [MCP-клиент: Claude Code, Cursor] ──(6, stdio)──▶ [mcp/server.py]   [Postgres/pgvector на Neon]
                                                                          ▲
                                                 [data/*.txt] ──(7)───────┘ ingestion
 агент ──(8)──▶ [Yahoo Finance] (get_stock_quote; аргумент от LLM)
```

| # | Граница | Что пересекает | Кто недоверенный |
|---|---|---|---|
| 1 | браузер → Vercel | вопрос + **вся история диалога** | пользователь |
| 2 | Vercel → Render | тот же JSON, проксируется как есть | всё, что прошло (1); плюс прямые запросы на Render в обход фронта |
| 3 | API → Postgres | SQL-запросы, параметризованы | — |
| 4 | **Postgres → промпт** | текст чанков | **автор любого документа** (indirect prompt injection) |
| 5 | API → LLM-провайдер | промпты, ключи | ответы модели — недоверенный вывод |
| 6 | MCP-клиент → сервер | вызовы tools | локальный процесс; модель клиента может быть под инъекцией |
| 7 | файлы → индекс | содержимое документов | автор документа |
| 8 | агент → внешний API | аргументы tool_call, которые сгенерировала LLM | LLM (то есть косвенно пользователь или документ) |

## 3. STRIDE по границам

| Угроза | Где | Текущая защита | Пробел |
|---|---|---|---|
| **S**poofing | (2) прямой вызов Render | `X-API-Key`, если задан `API_KEY` | на проде ключ не задан → F-03 |
| **T**ampering | (1) подделка истории | `role: Literal["user","assistant"]` | реплики `assistant` подделываются → F-11 |
| **T**ampering | (4)(7) отравленный документ | разделители и «это данные, не инструкции» в промпте | детектора нет; guardrail видит только вопрос → F-06 |
| **R**epudiation | все | — | нет аудит-лога запросов (кто, что спросил, какие tools) |
| **I**nfo disclosure | (4) чужие документы | — | ACL и тенантов нет: все видят всё → F-08 |
| **I**nfo disclosure | Vercel env | — | креды Neon во фронте → F-05 |
| **D**oS / denial of wallet | (1)(2) | rate limit 20/мин, семафор на 5 запросов, лимиты длины | лимит по IP за прокси, вероятно, общий для всех → F-04; раздувание истории → F-11 |
| **E**levation | (8) аргументы tools | калькулятор на `ast` с лимитами, проверка тикера | — |

## 4. OWASP Top 10 for LLM Applications (2025)

| ID | Риск | Статус | Защита сейчас / план |
|---|---|---|---|
| LLM01 | Prompt injection (прямая) | частично | LLM-guardrail; план: классификатор Prompt Guard 2 + red-team набор (этапы 5–6) |
| LLM01 | Prompt injection (indirect) | **слабо** | разделители в `tools/search.py`; план: санитизация при ingestion, canary-тесты |
| LLM02 | Раскрытие чувствительных данных | **нет защиты** | план: ACL-фильтр в SQL, тенант в ключе кэша (этап 5) |
| LLM03 | Supply chain | ок | `uv.lock`, pip-audit и npm audit в CI, gitleaks |
| LLM04 | Отравление данных и модели | частично | корпус пишут только мейнтейнеры; план: подпись источников при ingestion |
| LLM05 | Небезопасная обработка вывода | ок | React экранирует ответ, markdown и HTML не рендерятся; tools не исполняют вывод модели как код |
| LLM06 | Excessive agency | ок | 3 инструмента, только чтение; `MAX_STEPS=5`; калькулятор без `eval` |
| LLM07 | Утечка системного промпта | частично | guardrail; план: canary-строка в промпте + тест |
| LLM08 | Слабости векторного слоя | **нет защиты** | план: ACL до поиска, тест на «магнитный» документ |
| LLM09 | Дезинформация | меряется | critic + `evals/` (faithfulness, категория unanswerable) |
| LLM10 | Unbounded consumption | частично | лимиты длины, rate limit, семафор; пробелы F-04, F-11 |

## 5. Находки

Severity: Critical / High / Medium / Low / Info. Статус: fixed / partial / open.

| ID | Sev | Находка | Статус |
|---|---|---|---|
| F-01 | **Critical** | Фронт на Next.js 16.3.3: на эту версию есть advisory про RCE без аутентификации (GHSA-2464-fhr4-w9xw, GHSA-673q-mjm6-r5xr), SSRF в Image Optimization и cache poisoning. Найдено `npm audit` | **fixed**: обновлено до 16.4.3, `npm audit` → 0. Нужен передеплой на Vercel |
| F-02 | Medium | `get_stock_quote`: тикер (аргумент от LLM) подставлялся в URL без проверки, `AAPL/../../v7/...` уводил запрос на другой путь хоста Yahoo. Найдено ruff S310 / bandit B310 | **fixed**: allowlist-регулярка, тесты в `tests/unit/test_tools.py` |
| F-03 | Medium | Бэкенд на Render без аутентификации: `API_KEY` нет в `render.yaml`, прокси ключ не шлёт. Любой, кто знает URL, обходит фронт и тратит бюджет LLM | **partial**: прокси шлёт `X-API-Key` из `BACKEND_API_KEY`, в `render.yaml` добавлен `API_KEY`. Осталось задать значения в Render и Vercel |
| F-04 | Medium | Rate limit по `request.client.host`. За балансировщиком Render и прокси Vercel это, вероятно, IP прокси, то есть **один общий лимит на всех**: один пользователь выбирает лимит за всех. Счётчик в памяти и у каждого инстанса свой | open — проверить на этапе 6 |
| F-05 | Medium | В env проекта Vercel лежат креды Neon (`DATABASE_URL`, `PGPASSWORD`, …), хотя фронт базу не использует. **Вместе с F-01** RCE на фронте давала бы доступ к базе на запись | open: отключить интеграцию Neon от web-проекта или убрать переменные |
| F-06 | Medium | Indirect prompt injection: guardrail проверяет только вопрос, текст документов идёт в промпт main agent'а и critic'а. Документ может «уговорить» и агента, и критика | open — этапы 5–6 |
| F-07 | Low | CORS: без `ALLOWED_ORIGIN` → `allow_origins=["*"]`, `allow_headers=["*"]`. Credentials не используются, поэтому риск низкий. Найдено и semgrep (`wildcard-cors`) | **fixed**: по умолчанию cross-origin запрещён, заголовки по allowlist, тест |
| F-08 | Info | Нет тенантов и ACL: любой пользователь получает любой документ. Пока корпус общий — это by design, но блокер для реальных данных | open — этап 5 |
| F-09 | Low | `/api/ask` на Vercel: `request.json()` без try → невалидный JSON даёт необработанный 500 | open |
| F-10 | Info | Нет аудит-лога: при инциденте нельзя восстановить, кто что спрашивал и какие tools вызывались | open — этап 2 плана (трейсинг) |
| F-11 | Medium | История диалога целиком от клиента: можно подделать реплики `assistant` (подмена контекста, many-shot jailbreak), guardrail историю не видит. 10 сообщений × 8000 символов ≈ 20K+ токенов на **каждый** шаг агента → усиление стоимости | open — этап 5 |
