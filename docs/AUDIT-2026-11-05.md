# Аудит RAG MCP agent — 2026-11-05

База сравнения: `d83e3723a9ac594eadbe0b236a7827b4bc80306c` в
[subrosa5/rag-mcp-agent](https://github.com/subrosa5/rag-mcp-agent).
Проверены все Python-модули, HTTP/MCP-контракты, SQL, ingestion, eval,
веб-прокси/чат, зависимости и документация. Это аудит найденных проблем,
не доказательство отсутствия других дефектов.

## Главный вывод

Изначальная архитектура позволяла выдавать неподтверждённый ответ даже после
отрицательного вердикта критика. Промпты и четыре роли не обеспечивали
проверяемую связь каждого утверждения с источником. Ветка исправлений вводит
такую связь, запрещает выдачу отклонённых черновиков и проверяет границы тестами.
Фактический процент галлюцинаций до/после пока не измерен: live-inference
Groq/Cohere и доступ к действующему индексу в этом аудите не использовались.

## Актуальные решения и основания

Проверено по первичным источникам на дату аудита:

- Исходный Next.js 16.3.3 входит в affected range опубликованных критических
  advisories. Это проверка версии зависимости, не воспроизведение эксплуатации
  конкретного приложения. Выбрана исправленная ветка 16.4.5.
  [Next.js advisory](https://github.com/advisories/GHSA-2464-fhr4-w9xw),
  [use cache advisory](https://github.com/advisories/GHSA-673q-mjm6-r5xr).

- Groq поддерживает строгий JSON Schema у GPT-OSS, но не объединяет Structured
  Outputs и tool use в одном запросе. Поэтому введён отдельный вызов генерации
  после инструментов. Schema гарантирует структуру, не истинность.
  [Groq Structured Outputs](https://console.groq.com/docs/structured-outputs).
- Cohere перечисляет `rerank-v5.0-fast` и `rerank-v5.0-pro` как мультиязычные
  варианты. Добавлен настраиваемый fast-default; превосходство на конкретной базе
  не измерено. До выпуска сравнить с прежним v3 и pro по качеству, p95 и цене.
  [Cohere Rerank](https://docs.cohere.com/docs/rerank-overview).
- Postgres/pgvector остаётся разумной инфраструктурой для текущего объёма.
  Замена на отдельную vector DB без нагрузочного теста не обоснована.
  [pgvector, hybrid search](https://github.com/pgvector/pgvector#hybrid-search).
- Официальный MCP Python SDK поддерживает v2, MCPServer и современный Client;
  версия должна совпадать с импортами. Удалённый MCP требует отдельного проекта
  по аутентификации, а не просто открытия stdio-сервера в интернет.
  [Официальный SDK](https://github.com/modelcontextprotocol/python-sdk).

Это инженерный выбор для данного кода, не доказательство рыночного спроса или
«лучшая модель для всех». Старую embedding-модель сохранили, чтобы не смешивать
несовместимые пространства векторов.

## Продуктовая рекомендация

Выбрать узкую задачу: **проверяемый помощник по регламентам и runbook для небольшой
инженерной команды**, доступный из IDE через MCP и через чат. Текущий корпус
(онбординг, деплой, лимиты) подходит для такого пилота. Основное обещание:
«показывает основания ответа и сообщает, когда их недостаточно».

Приоритеты следующего этапа:

1. Подключить один реальный источник (например, GitHub docs) с версиями,
   обновлением и удалением; показывать ревизию и дату документа. Это важнее
   добавления ещё одного агента или провайдера.
2. Закрытый пилот с сессионной авторизацией веб-прокси. Для нескольких организаций
   — tenant_id, ACL-фильтрация до обоих поисков и RLS; проверка cross-tenant утечек.
3. Отдельный размеченный набор реальных вопросов, включая неоднозначность,
   отрицания, конфликтующие версии, prompt injection в документах и follow-up.
   Калибровать порог на development split, публиковать результат на held-out.
4. Собирать wall-clock p50/p95, процент полезных ответов, unsupported claim rate,
   over-refusal rate и полную стоимость (LLM + embed + rerank). Порог релиза
   согласовать с владельцем данных; не подменять confidence числом rerank score.
5. Для роста нагрузки — пул БД, централизованные квоты, отмена запросов и общий
   deadline, трассировки ошибок, инкрементальная индексация без TRUNCATE.

## Остаточные ограничения

- Точное наличие цитаты **не доказывает entailment**. Критик той же модели может
  повторить ошибку генератора; отдельная CRITIC_MODEL доступна, но не измерена.
- Защита prompt injection вероятностная. Документы и история остаются недоверенными.
- Нет ACL/tenant isolation, пользовательской авторизации веб-прокси и remote MCP OAuth.
  API_KEY — общий сервисный ключ, а не корпоративная identity-система.
- FTS — не BM25. Термы объединяются через OR для полноты поиска, поэтому
  общие слова могут давать лишних кандидатов; точность зависит от реранкинга.
  Query expansion и специализированная tokenization требуют отдельного eval.
- Чанкинг по символам и hard truncation истории сохранены. Нужны проверки
  границ предложений/таблиц и лимитов tokenizer конкретного embedder.
- Сохраняется полная переиндексация с блокировкой читателей; нет document ACL,
  отдельных версий индексов и безопасного online-switch между embedding-моделями.
- Лимиты в памяти одного процесса, общий ключ делит квоту между клиентами.
- Таймауты на внешние вызовы есть, общего принудительного deadline/cancellation нет.
  Уход браузера или timeout прокси не отменяет выполняющуюся синхронную цепочку.
- Telemetry считает только завершившиеся успешные LLM-вызовы. Не включает ошибки,
  провайдерные retry, rerank/embed, сеть и инфраструктуру. Это не billing.
- Yahoo quote — best effort, возможны задержки/блокировки; не основа для финансового продукта.
- Живой eval не выполнен; нет измеренного улучшения hallucination rate, latency или cost.
  Объявлять продукт production-ready или «без галлюцинаций» пока нельзя.

## Порядок выпуска

Изменения подготовлены в отдельной ветке. Выпуск требует staging-индекса с новой
metadata, синхронной настройки API_KEY на Render и RAG_AGENT_API_KEY на Vercel,
живого eval и проверки актуального reranker на аккаунте. Main/production в рамках
аудита не переключались. Пошаговая инструкция — в README.

## Выполненная проверка

- **60 тестов прошли** на Python 3.12.14 и Python 3.14.7. Использовалась отдельная
  локальная PostgreSQL 17 + pgvector база, не production. Покрыты SQL-поиск,
  rollback неудачной переиндексации, несовпадение моделей, MCP discovery,
  невалидные аргументы, цитаты, отказы критика, лимиты и контракты API.
- Ruff check и format check прошли. Frontend ESLint прошёл.
- Next.js **16.4.5** production build с `--webpack` прошёл, включая TypeScript.
  Локальный Turbopack падал на запрещённом bind порта; это ограничение окружения.
- После обновления зависимостей `npm audit` не сообщает известных уязвимостей.
  Dev-зависимость minimatch у typescript-estree закреплена scoped override на
  11.0.1; её CommonJS API совместим с используемым вызовом, ESLint проверен.
  Override следует удалить, когда upstream поднимет свой диапазон.
- `pip-audit` проверил 64 установленных Python-пакета: известных advisories нет.
  `pip check` не нашёл конфликтов зависимостей. Это проверка опубликованной базы
  advisories на дату запуска, не доказательство отсутствия всех уязвимостей.
- Live Groq/Cohere, production migration, нагрузочные испытания и отдельная
  проверка self-hosted ML-моделей **не выполнялись**.
